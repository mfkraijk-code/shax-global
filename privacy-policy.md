The information processed depends on the features enabled and how the Bot is configured. The operator must keep this policy aligned with the Bot’s actual code and practices.

## 2. Information that may be processed

Depending on enabled features, SHAX may process:

- **Discord identifiers:** user IDs, server IDs, channel IDs, role IDs, and message IDs needed to run features.
- **Membership and role information:** membership events and role assignments used for verification, permissions, and server administration.
- **Message information:** message text, links, message references, and moderation results where a feature needs to inspect or record them.
- **Ticket information:** support requests, application answers, partnership or order inquiries, ticket messages, and transcripts if enabled.
- **Operational information:** command activity, error logs, event records, and staff actions needed for operation, troubleshooting, and security.
- **Presence or activity information:** online status or activity data only if the relevant feature is enabled and the Bot actually processes it.

The operator should remove any categories that do not apply and add any additional categories the Bot actually collects.
